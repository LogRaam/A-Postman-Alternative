## `tests/auth.test.mjs`

Authentication from the Auth tab, and the rule that every typed field of a request can use {{variables}}.

### The Authorization header

- Bearer sends the token as typed
- Basic encodes user:password in Base64, accents included (UTF-8)
- none, or an empty Bearer token, sends no header and an empty token is reported
- the Auth tab becomes the request's Authorization header
- an Authorization header typed in the Headers tab wins, and the user is told
- a draft saved before the Auth tab existed opens with no authentication

### Variables reach every typed field

- a {{token}} in the Bearer token is resolved from the environment
- every text field of DRAFT_FIELDS is resolved, except the choices named in DRAFT_CHOICE_FIELDS

## `tests/collections.test.mjs`

Saved requests: collections, one level of folders, and what Save, rename, remove and import do to them.

### Saving

- a request is saved in its folder, or at the top of the collection
- the saved draft is a copy: editing the editor afterwards changes nothing saved
- Save on an open request replaces its draft and nothing else
- a blank name falls back to a default rather than an empty label

### Finding, renaming, removing

- a request is named by its path: collection, folder, request
- rename finds a collection, a folder or a request by id
- removing a folder removes the requests in it, and only those
- the list given is never changed, so undo can put it back

### Importing collections

- new collections, folders and requests are added; ones already here are kept as they are
- importing the same file twice changes nothing

## `tests/environments.test.mjs`

Environments: {{variables}} resolved when a request is sent, so one saved request works everywhere.

### Resolving a request

- replaces {{name}} in the address, parameters, headers and body
- the editor keeps the {{names}}: resolving never changes the draft it is given
- an unticked variable does not count, and an unknown name is left as typed and reported
- with no environment selected, every reference is reported
- the warning names the variables and the environment, or says none is selected
- lists the names an address refers to, each once

### Managing environments

- rename keeps the old name when the new one is blank
- remove takes one environment out and leaves the list given untouched
- importing adds new environments and keeps the ones already here as they are

## `tests/request.test.mjs`

What the editor's draft becomes when it is sent: the address, the headers, the body and the warnings.

### The address

- adds https when the address has no scheme
- appends enabled parameter rows after the query the address already has
- skips unticked rows and rows without a name
- refuses an empty address with an example of a good one
- refuses schemes other than http and https

### Headers

- are sent in the order typed
- a header the browser forbids is not sent, and the user is told
- forbidden names include the proxy- and sec- families, in any case

### The body

- a JSON body is checked and gets a JSON content type when none was typed
- a content type the user typed is kept as typed
- invalid JSON stops the send with the parser reason
- GET and HEAD send no body, and the user is told
- raw text is sent as typed with no content type added

## `tests/state.test.mjs`

The app's state and what it keeps in the browser: one place for every value, saved under keys that never change.

### What is kept in the browser

- the storage keys never change: renaming one would lose users' data on their next visit
- a damaged or missing slice reads as its fallback, never as garbage
- without any storage at all the app still starts, with an empty workspace

### The state

- a change is saved and survives a reload
- listeners hear which slices changed and which controller changed them
- removing the open request clears the link to it, and listeners hear that too
- deleting the active environment leaves no environment active
